Use Menu for **commands**. For a list of values the user picks from, use
[`Select`](/components/select). For a rich panel (inputs, links, cards), use
[`Popover`](/components/popover).

## Link items

`MenuLinkItem` renders a real `<a>` with proper menu semantics — it stays in
the roving tab order and closes the menu on activation.

Menu is framework-agnostic. Pass `render` to integrate with any router:

```tsx
// Plain anchor
;<MenuLinkItem href="/profile">Profile</MenuLinkItem>

// Next.js
import Link from 'next/link'
;<MenuLinkItem render={<Link href="/profile" />}>Profile</MenuLinkItem>

// TanStack Router
import { Link } from '@tanstack/react-router'
;<MenuLinkItem render={<Link to="/profile" />}>Profile</MenuLinkItem>
```

## RTL

Menu uses logical properties in the parts that matter — `MenuShortcut` sits
at `ms-auto` (the reading-end of the item), and `MenuSubTrigger`'s chevron
flips with `rtl:-scale-x-100`.

Sides are **physical** — `left` / `right` do not flip with `dir`. This is
the same policy as `Tooltip` and `Popover`; in a bilingual app, pick the
side from the current direction at the call site. `MenuSubPopup` defaults
to `side="right"` (assumes LTR); in an RTL page, pass `side="left"` — the
chevron flips automatically to match, so the visual and semantic
direction stay aligned.

**Portal gotcha:** both `MenuPopup` and `MenuSubPopup` are portaled to
`document.body`, so they do not inherit `dir="rtl"` from any wrapper. In a
real Persian app, `<html dir="rtl">` covers it. In this docs preview, the
demo passes `dir="rtl"` on both popups directly — the same exception
documented for `Tooltip`, `Popover`, `Select`, `Combobox`, `Sheet`,
`Dialog`, and `Drawer`.
